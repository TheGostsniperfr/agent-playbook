# GitHub profile home page

A great profile page = a few self-hosted, theme-aware SVGs + one live data card regenerated by a
scheduled workflow + plain Markdown for everything clickable.

## Where it lives
- Org: `profile/README.md` in `<org>/.github` (public); `.github-private` for members only.
- User: `README.md` in the repo named like the username.
- GitHub renders Markdown + sanitized HTML (`picture`, `source`, `img`, `a`, `p align`, `sub`,
  `details`, tables). No CSS, no scripts, no iframes: visuals come from images, mostly SVG.

## Steps
1. Ask for (or propose) ONE looping scene from the project's world, a tagline under 60 chars, a
   scope line, and the brand colours if any. Reuse the project's real logo or mascot, never a
   generic stand-in.
2. Define two palettes (dark, light) with the same roles: bg gradient, ink, muted, two accents,
   surfaces. Re-check contrast for light; never just invert.
3. Pick an OFL display face + medium weight from Google Fonts; commit the .ttf and OFL.txt.
4. Write ONE Python generator that outputs `banner.dark.svg` and `banner.light.svg` (1280x400,
   rounded clip frame, text left, scene right). Convert all text to paths with fontTools:
   `scripts/svgkit.py` (in this skill's folder) has `Fonts.path()`, `iso()`, `poly()`, `box()`
   and `keyframes()`; copy it next to your generator.
5. Animate with CSS `@keyframes` inside `<style>`: 3-4 motions, 2-10 s loops, staggered
   `animation-delay`. Animate only transform, opacity, fill, stroke-dashoffset. No CSS variables
   inside keyframes: generate explicit keyframes. For lines that draw themselves use
   `pathLength="100"` + `stroke-dasharray:100`. Add
   `@media (prefers-reduced-motion: reduce){*{animation:none!important}}` with a good still frame.
6. Isometric scenes: x' = (x-y)*cos30, y' = (x+y)*sin30 - z; cubes = 3 polygons (top, left, right).
7. Live card: `profile_stats.py` calls the GitHub REST/search API (public data only: repo count,
   open issues, issues with a ready label, PRs merged in 30 days, latest releases,
   project-specific content counts) and writes `stats.dark.svg`/`stats.light.svg` with the same
   fonts as paths.
8. Workflow: start from `assets/profile.yml` (daily cron + workflow_dispatch + push on generator
   changes; `permissions: contents: write`; pip install fonttools; run both scripts; commit
   `profile/` only if changed).
9. README: banner (linked to docs) -> shields.io badges (flat-square, banner colours) -> two short
   paragraphs -> live card -> repo table (repository / what it does / built with) -> architecture
   picture in both themes linked to docs -> how-we-build bullets -> get-involved links (docs,
   contributing, good first issues, board, security).
10. Every image goes through `<picture>` with `prefers-color-scheme` dark/light sources and an
    `<img width="100%" alt=...>` fallback. Assets may live in another repo via
    raw.githubusercontent.com URLs so they update without touching the profile repo.

## Gotchas
- No script or external resource inside SVG (Camo + CSP strip them); embed everything.
- Safari can ignore media queries inside SVG for theming: switch themes via `<picture>`, not
  inside one SVG.
- Whitespace between inline images becomes gaps; keep side-by-side images on one line.
- Camo caches images; rename or add a query string for an instant refresh.
- Text >= 14 px at 1280 width; banner under ~60 KB; `role="img"` + `aria-label` on each SVG.
- The workflow token only reads public data; never put a personal token in the profile repo.

## Verify before publishing
- Preview headless in Chromium at two moments, both themes:
  `chromium --headless=new --no-sandbox --use-angle=swiftshader --window-size=1280,400 --virtual-time-budget=4000 --screenshot=out.png file://.../banner.dark.svg`
  (cairosvg shows only the first frame).
- Fix overlaps with the title, check the reduced-motion frame, run the stats workflow once.
- Check the page on desktop and phone in both GitHub themes; every link and badge goes somewhere real.
