# Phase 3 · Docs as code and diagrams

**Goal:** one place that explains the whole system, decisions recorded as ADRs, and diagrams
generated from a model and checked against what is deployed, so docs cannot silently drift.

## Decisions to take

| Decision | Arffornia default | Why |
|---|---|---|
| Where cross-repo docs live | A central `docs` repo, MkDocs Material on GitHub Pages; repo-specific docs stay in each repo | Ecosystem never described as a whole; one site for contributors and agents |
| Decision records | ADRs (`docs/decisions/NNNN-*.md`, front-matter status `proposed`/`accepted`/`superseded`) for anything that spans components or someone may want to undo | Agents must tell a deliberate choice from an accident; reviews point to an ADR |
| Who accepts ADRs | Agents write them as `proposed`; only the owner flips to `accepted` | Decisions belong to the owner |
| Diagrams | Generated from one model with several views (Noodle), both themes, exports committed; Mermaid only for small local sketches | Diagrams as code can be linted and diffed |
| Source of truth for infra facts | Discovery from rendered manifests (`noodle discover k8s`) matched to the model | Drawn-from-docs diagrams were wrong twice |
| Toolchain pin | `mkdocs>=1.6,<2` | MkDocs 2.0 breaks Material plugins |
| Org front page | Org profile README with animated, theme-aware SVGs regenerated by a daily workflow | First impression for contributors; the owner asked for "impressive" |

## Steps (agent)

1. Scaffold the site: architecture, components (one page each), contributing (workflow, standards,
   AI agents, diagrams), decisions, roadmap, glossary. Concise, linked from every README.
2. Write ADR-0001 "record decisions", then one ADR per cross-cutting choice the audit surfaced.
3. Model the system once; derive views by question ("how does a player log in?"), not by layer.
4. Run discovery on the real manifests; resolve every unmatched element or list it as drift.
5. Export both themes; **look at every PNG** (lint passes are not enough, see below).
6. Keep a field report on the diagram tool itself for its maintainer (the owner wrote Noodle).
7. Org profile: banner, live numbers card, ecosystem picture, repo table, "how we build", links.

## Human touchpoints

- Accept or veto proposed ADRs (on the chantier page, one click each).
- Give brand assets at the start (logo, colours). We drew three cubes; the logo is a crafting table.

## Anti-patterns we hit

- **Headless draw.io crops exports wider than ~4000 px** and stretches the rest, silently: a whole
  column disappeared. Cap scale at `min(2, 3900 / width)`; prefer SVG.
- **Lint accepted text that draw.io wraps** (font fallback, zero margin). Visual review of every
  export is part of done.
- **CSS custom properties inside `@keyframes`** were unreliable in GitHub-rendered SVG. Generate
  explicit keyframes. Use `pathLength="100"` for line-drawing, honour `prefers-reduced-motion`,
  convert text to paths (fonts are not loaded in `<img>` SVGs), serve via `raw.githubusercontent`.
- **Preview animations headless** in Chromium with `--virtual-time-budget` before publishing.
- **Text baked into images** cannot be translated. Keep words out of PNGs for player-facing art.
- **Chart objects without a namespace** landed in `default` in discovery: pass the Argo CD
  destination namespaces.
- **Inline YAML tags** (`!!python/name`) in `mkdocs.yml` failed in flow style; use block style.
